## 开发原则

1. 按功能拆分小 PR；
2. 每个 PR 只做一件事；
3. 主分支保持可运行；
4. PR 描述必须包含功能描述、实现思路和测试方式；
5. 若复用本人历史项目代码或思路，必须在 PR 中注明来源；
6. 第三方依赖必须在 README 中列明；
7. 每次提交都需要有明确功能目的，避免无意义 commit。

#### 当前思路

项目不采用“一次性 AI 生成剧本”的方式，而是采用多阶段工作流：

```text
小说输入
↓
章节切分
↓
事实抽取
↓
角色 / 事件 / 伏笔 / 时间线记忆库
↓
剧本专家 Agent
↓
剧本医生 Agent
↓
YAML Schema 校验
↓
自动修复
↓
结果预览与导出
```

## 风险记录

| 风险 | 解决思路 |
|---|---|
| AI 长文本改编时遗忘前文 | 使用事实记忆库和上下文压缩 |
| AI 输出 YAML 格式错误 | 使用 Schema 校验和自动修复 |
| 剧本内容太像 AI 改写 | 加入剧本医生 Agent 和剧作规则库 |
| 人物性格前后不一致 | 建立角色记忆表和一致性检查 |
| 最后提交不符合规则 | 使用小 PR 和持续 commit 记录 |
